FlowSync — Integrated Order, Inventory & Warehouse
Management System

Project Documentation

1. Introduction / はじめに

English:

FlowSync is a full-stack business web application built to manage the complete lifecycle of customer orders, product inventory, and warehouse fulfillment on a single platform. It connects the customer-facing ordering process with backend inventory control and warehouse status tracking, so that stock levels stay accurate as orders are placed and fulfilled.

日本語:

FlowSync は、顧客注文・商品在庫・倉庫出荷業務のライフサイクル全体を一つのプラットフォームで管理するために開発されたフルスタック業務アプリケーションです。顧客側の注文プロセスと、バックエンドの在庫管理・倉庫ステータス追跡を連携させることで、注文の発生と処理に応じて在庫数量を正確に保ちます。

2. Project Overview / プロジェクト概要

English:

The platform allows customers to browse an active product catalog, place orders, and track order status through to delivery. Every order is validated and processed on the server: stock availability is checked, inventory is deducted transactionally, and the order total is calculated from server-side product data rather than client input. Administrators and warehouse managers manage the product catalog, monitor multi-warehouse inventory, execute inter-warehouse stock transfers, audit operational actions, and move orders through a defined fulfillment and warehouse pick/pack workflow.

日本語:

本プラットフォームでは、顧客が有効な商品カタログを閲覧し、注文を行い、配送までの注文ステータスを追跡できます。すべての注文はサーバー側で検証・処理されます。在庫の有無を確認し、トランザクション処理により在庫を減算し、注文合計はクライアントからの入力ではなくサーバー側の商品データに基づいて算出されます。管理者および倉庫担当者は商品カタログの管理、複数倉庫にまたがる在庫の監視、倉庫間在庫移動の実行、業務操作の監査ログ確認、および定義された出荷・倉庫ピッキング/梱包ワークフローに沿った注文の処理を行います。

3. Problem Statement / 課題

English:

Businesses handling both online orders and physical inventory often struggle to keep stock counts accurate in real time, leading to overselling, delayed fulfillment, and manual reconciliation between order systems and warehouse floors. FlowSync addresses this by tying order creation and inventory deduction together in a single atomic transaction with database-level locking, providing multi-warehouse stock transfer state management, maintaining an immutable audit log of all critical changes, and giving staff a clear, status-driven view of where each order stands from placement to dispatch.

日本語:

オンライン注文と実在庫の両方を扱う事業者は、リアルタイムでの在庫数の正確な把握に苦労することが多く、売り越しや出荷遅延、注文システムと倉庫現場との手作業による突合が発生しがちです。FlowSync は、注文作成と在庫減算をデータベースロックを伴う一つの原子的な処理として結び付け、複数倉庫間の在庫移動ステータス管理、すべての重要操作に対する不変の監査ログ、および注文が受付から出荷までどの段階にあるかをステータスベースで明確に確認できる仕組みを提供することで、この課題に対応します。

5. Key Features / 主な機能

  • English: Fine-grained Role-Based Access Control (RBAC) with ADMIN, WAREHOUSE_MANAGER, SALES, and CUSTOMER roles
    日本語: ADMIN、WAREHOUSE_MANAGER、SALES、CUSTOMER ロールに対応したきめ細やかなアクセス制御
  • English: Multi-Warehouse Stock Transfer System with a 5-stage lifecycle (PENDING → APPROVED → IN_TRANSIT → COMPLETED / CANCELLED)
    日本語: 5段階のステータス遷移（PENDING → APPROVED → IN_TRANSIT → COMPLETED / CANCELLED）と自動在庫相殺・復元ロジックを備えた複数倉庫間在庫移動機能
  • English: Immutable Audit Logging tracking actor, action, target entity, previous value, new value, and timestamp
    日本語: 操作者、アクション、対象エンティティ、変更前の値、変更後の値、タイムスタンプを永続記録する不変の監査ログ機能
  • English: High-concurrency transaction management with pessimistic write locking (SELECT ... FOR UPDATE) and optimistic locking (@Version)
    日本語: 同時注文による売り越しを防ぐ悲観的ロック（SELECT ... FOR UPDATE）と在庫更新の楽観的ロック（@Version）
  • English: Product catalog with real-time stock levels, warehouse locations, and low-stock threshold monitoring
    日本語: リアルタイムの在庫数、倉庫ロケーション情報、発注点管理を含む商品カタログ
  • English: Transactional order placement with server-side price calculation and stock validation
    日本語: サーバー側での価格計算と在庫検証を伴うトランザクション処理による注文登録
  • English: Order status (PLACED → CONFIRMED → PROCESSING → SHIPPED → DELIVERED) and pick status (PENDING_PICK → PICKED → PACKED → SHIPPED) tracking
    日本語: 注文ステータスおよびピッキング/梱包ステータスの進捗追跡
  • English: Unified Admin & Operations dashboard with order, inventory, and low-stock overview
    日本語: 注文・在庫・低在庫状況を一元的に把握できる管理者・運用ダッシュボード
  • English: Scheduled background job (@Scheduled) to detect and log low-stock products dipping below reorder level
    日本語: 低在庫商品を検知しログに記録する定期バックグラウンドジョブ
  • English: Centralized exception handling returning sanitized, structured JSON error responses
    日本語: 整形されたエラーレスポンスを返す一元化された例外処理

6. System Architecture / システム構成

English:

The frontend (React + TypeScript + Vite) communicates with the Spring Boot backend over REST APIs secured by stateless JWT authentication. The backend is organized into Controller, Service, Repository, and Entity layers, with MySQL 8 as the relational data store and an in-memory H2 database for automated test suite execution.

日本語:

フロントエンド（React + TypeScript + Vite）は、ステートレスな JWT 認証で保護された REST API を介して Spring Boot バックエンドと通信します。バックエンドは Controller・Service・Repository・Entity の各層に整理されており、リレーショナルデータストアとして MySQL 8 を使用し、自動テストには高速な H2 インメモリデータベースを活用しています。

React (TypeScript + Vite) Frontend
    ↓
REST API / JWT Authentication Filter
    ↓
Spring Boot Backend (Controller Layer → Service Layer with @Transactional & Concurrency Locks)
    ↓
MySQL 8 Database (Local & Cloud via Spring Data JPA / Hibernate) + H2 Database (Automated Tests)
